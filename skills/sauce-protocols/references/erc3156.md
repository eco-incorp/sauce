# ERC-3156

Standard interface for flash loans (EIP-3156). Provides flashLoan, flashFee, and maxFlashLoan functions for any conforming lender. Many protocols lend flash loans through an interface of their own instead, which this one does not call.

## Category

infrastructure | Chains and addresses: [registry/erc3156.md](registry/erc3156.md)

## Key Operations

- **flashFee**: Query the fee for a flash loan of a specific token and amount
- **maxFlashLoan**: Query the maximum flash loan amount for a token
- **flashLoan**: Execute a flash loan (borrow and repay in same transaction)

## Typed templates for the raw compiler (not for `sauce compile`)

These import the protocol's ABI from `./abis`, the way the registry compiles them with the raw
compiler; `sauce compile` has no such module. In a program for a chain, name the contract by its
namespace, or import its ABI from `./protocols/<slug>/<Export>.json` as the registry file at the
top of this document shows, and write SauceScript's values (`~0`, not `type(uint256).max`).

```typescript
// Query flash loan fee
import { FlashLenderABI as IFlashLender } from "./abis";
function main(lenderAddress: Address, token: Address, amount: Uint256): Uint256 {
  const lender = IFlashLender.at(lenderAddress);
  return lender.flashFee(token, amount);
}

// Query max flash loan amount
import { FlashLenderABI as IFlashLender } from "./abis";
function main(lenderAddress: Address, token: Address): Uint256 {
  const lender = IFlashLender.at(lenderAddress);
  return lender.maxFlashLoan(token);
}
```

## Deployments and ABI

The registry's addresses per chain, how a program names each contract there (a namespace, or

## Notes

- Standard interface (EIP-3156), not a specific deployment - no fixed addresses
- Conforming lenders implement all three functions: Maker's DssFlash (DAI) and Aave's GHO flash minter (GHO), for example, or an ERC-3156 adapter in front of another protocol's flash loans. `maxFlashLoan(token)` is non-zero for a token the lender lends
- Protocol-specific flash loans are not ERC-3156, and `flashFee`/`maxFlashLoan` revert there: Aave V3's Pool (`flashLoanSimple`/`flashLoan`, receiver callback `executeOperation`, premium `FLASHLOAN_PREMIUM_TOTAL` in basis points), Balancer V2's Vault (`flashLoan(recipient, tokens, amounts, userData)`, callback `receiveFlashLoan`) and Uniswap V3 pools (`flash`, callback `uniswapV3FlashCallback`). Call those through their own protocol's interface
- Receiver contract must implement `onFlashLoan(address,address,uint256,uint256,bytes)` callback
- Must approve lender to pull back amount + fee before callback returns
- Flash loan must be fully repaid within the same transaction (atomic)
- The fee is each lender's: read it with `flashFee(token, amount)` before borrowing
