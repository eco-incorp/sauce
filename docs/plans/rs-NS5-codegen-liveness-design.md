## Design (ns5Design)

ROOT CAUSE (confirmed): the consume-vs-copy decision is NOT driven by scope.rs at all. `scope::analyze` (codegen.rs:441) builds a ScopeTree with per-local LiveRange (scope.rs:109), but it is consumed ONLY for stack-vs-memory Placement (via compute_spill_slots) and then discarded. The consume decision uses `last_use_flags` (codegen.rs:3028) — a linear approximation producing Vec<bool>, one per Expr::Local occurrence in emission order, replayed positionally in `read_local` (codegen.rs:2669: `if last_use { roll_to_top }` = SSWAP/consume, else `dup` = SDUP/copy). `collect_statement_locals` (codegen.rs:3069) tags each occurrence (LocalId, declared_outside:bool); a local declared outside the enclosing branch is force-copied. In the repro, `sr4` is declared in the outer if-arm and its only reads are the two arms of the ternary (which eval_order rewrote to an inner Stmt::If BEFORE codegen — scope.rs:472 rejects a raw Conditional). Relative to that inner if, sr4 is `outer` → both arm reads copied → slot never reclaimed → outer arm ends [cl,sr4] vs empty else [cl] → DivergentBranches (codegen.rs:1155).

KEY FINDING that shapes the fix: the existing single-interval LiveRange is INSUFFICIENT. sr4's two reads are in sibling arms; walk order gives last_used_at = only ONE arm's read. For the inner-if arms to merge, BOTH arm reads must consume symmetrically (each is its own path's last use), not just the globally-last one. So a naive Path-B (Codegen holds ScopeTree; read_local consumes iff occurrence-point == last_used_at) is WRONG — it consumes one arm, copies the sibling, still diverges. A scope.rs-threaded fix would require EXTENDING LiveRange to per-arm dead-out, a bigger change.

RECOMMENDED FIX (structural, self-contained in codegen.rs — "symmetric-arm consume"): (1) widen the occurrence tag from (LocalId, bool) to a 3-state {Copy, InnerConsumable, ArmForcedConsume}. (2) In collect_statement_locals's If arm (codegen.rs:3102-3157) — which already walks then/else into `out` separately — record each arm's occurrence index range; compute symmetric = {outer locals read in BOTH arms}; for each such L keep it only if (a) L is dead after this if (tail-scan the enclosing block's statements after I; block-scoping guarantees L can't be read past its declaring arm) AND (b) the current invocation is an IF-ARM body (pass a `container: {Root|IfArm|LoopBody}` down — NEVER fire under Root/LoopBody). For each surviving L, set the LAST occurrence in EACH arm's range to ArmForcedConsume (earlier same-arm reads stay Copy). (3) last_use_flags reverse-walk (codegen.rs:3053-3058): ArmForcedConsume → flag=true unconditionally (bypass the seen-set); other kinds unchanged. read_local (codegen.rs:2653) needs NO change — it replays flags positionally. Optionally hold scope::analyze's ScopeTree on Codegen and answer "dead after I" via LiveRange.last_used_at vs the if's scope span instead of a tail scan, but the symmetry half must stay structural, so the tail scan is simpler and needs no ScopeTree threading.

## Blast radius

Baseline: 1049 lib tests (1048 pass, 1 ignored = the a_ternary_... repro) + tests/ecoswap.rs (ignored). codegen.rs alone has ~30 exact-bytecode assert_eq!, ~42 simulate() execution tests, 249 test fns; more bytecode-pinning tests live across other modules — collectively the 1000+ byte-pins the task cites. A GLOBAL switch to precise CFG backward liveness would change the SDUP↔SSWAP choice for EVERY outer-local read inside control flow that is dead-on-all-paths → different bytecode for a large fraction of the byte-pinning corpus → mass perturbation (high risk, effectively a re-baseline). The RECOMMENDED structural symmetric-arm change perturbs ZERO currently-compiling programs: it fires only when an outer local is read in ALL arms of an inner if, dead after it, AND that if sits inside an if-arm — and a lingering branch-local ALWAYS diverges there today (the merge compares Vec<Option<LocalId>> by content, so a sibling arm holding a different branch-local/None at that depth already errors), so every program matching the pattern currently ERRORS (no baseline bytes to preserve). Verified the existing branch tests are untouched by the Root/LoopBody gate: if_arms_sharing_an_outer_local_do_not_falsely_diverge, a_shared_outer_local_read_differently_in_each_arm_compiles (both: local at ROOT, if at Root → gate blocks fire), a_local_declared_and_used_within_one_arm_is_consumed_not_copied (arm-local, already InnerConsumable), and the `if(a){let b} return a`→DivergentBranches negative test (b not read in both arms → still errors).

## Minimal-scope verdict

FEASIBLE. A minimal-scope fix that leaves all currently-COMPILING bytecode byte-identical and only resolves the would-be-error case exists: the recommended structural symmetric-arm consume, gated on container==IfArm (never Root/LoopBody) + read-in-every-arm + dead-after-if. Because a lingering branch-local slot always produces DivergentBranches at its enclosing if (merge compares stack contents, not just depth), the exact pattern the fix newly consumes can only occur in programs that currently FAIL — so making them compile changes no existing output. ONE residual, deliberately called out: if the enclosing arm is syntactically DIVERGING (ends in return/revert), its post-merge shape is discarded (if_statement's (None,Some)/(Some,None) arm), so a symmetric-dead local lingering inside it compiles TODAY; the fix would alter that arm's (still-executed, behaviorally-equivalent) bytecode. No test in the suite exercises that shape. Recommendation: implement the structural fix and confirm byte-identity empirically with a full `cargo test -p sauce-core` (expect only the two ignored tests to flip to pass); if the diverging-arm residual matters, add gate (e) suppressing the fire when the arm diverges (ir::diverges is already available and used at codegen.rs:1131). Lowest-risk path = structural symmetric-arm consume, NOT a global precise-liveness rewrite.
